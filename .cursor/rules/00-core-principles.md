# עקרונות ליבה

הכללים כאן חלים על **כל** פרויקט ועל כל היבטי התעשייה: פיתוח, אבטחה, בדיקות, תשתית, פרטיות, שיווק, עסק ותיעוד.

## סדר עדיפויות
1. אבטחה ופרטיות המשתמש
2. יציבות ה-production (main חייב לעבוד ללא באגים)
3. נכונות פונקציונלית
4. תחזוקתיות וקריאות
5. מהירות פיתוח

## כללי התנהגות של ה-Agent
- לפני כתיבת קוד: קרא את הקוד הקיים, את `docs/` ואת הכללים הרלוונטיים. אל תנחש.
- שינוי קטן ומתמקד אחד בכל פעם. אל תבצע refactor שלא התבקש.
- כל שינוי התנהגות מלווה בבדיקות באותו PR.
- לעולם לא לדלג על בדיקות, hooks או CI (`--no-verify`, `skip`, `@ts-ignore` בלי הסבר) כדי "לעבור".
- לעולם לא לכתוב סודות, מפתחות, טוקנים או נתוני משתמשים אמיתיים בקוד, בלוגים, בקומיטים או בצ'אט.
- פעולות הרסניות או בלתי הפיכות (מחיקת ענף, force push, migration הרסני, מחיקת נתונים) - עצור וקבל אישור מפורש.
- אם הבריף סותר כלל, או חסר מידע שמשנה ארכיטקטורה - שאל את המשתמש במקום להניח.
- בסיום משימה: דווח מה שונה, אילו בדיקות רצו ומה התוצאה, ומה נשאר פתוח.

## תקנים שהפרויקטים מתיישרים איתם
OWASP Top 10 / ASVS, 12-Factor App, Semantic Versioning, Conventional Commits, WCAG 2.2 AA, Core Web Vitals, ISO/IEC 25010 (איכות תוכנה), DORA metrics, GDPR + חוק הגנת הפרטיות הישראלי (כולל תיקון 13).

## שפה
- תקשורת עם המשתמש: עברית.
- קוד, שמות משתנים, קומיטים, PR, שמות ענפים: אנגלית.
- UI: לפי שוק היעד (ברירת מחדל: עברית עם RTL מלא + i18n מוכן לשפות נוספות).
